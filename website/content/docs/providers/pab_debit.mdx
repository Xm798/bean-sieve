## 账单下载方式

登录[平安银行个人网上银行](https://bank.pingan.com.cn/m/main/index.html)，查询借记卡交易明细后导出 Excel 文件。扫码登录不需要安装安全控件。

文件名同时含「平安」和「借记」时（如 `平安银行借记卡流水.xlsx`）直接识别；其他文件名按内容识别，见下一节。

## 支持的文件格式与识别方式

<ProviderFacts id="pab_debit" />

文件名不符合时，Bean-Sieve 会读表格前 5 行，同时找到「付款方姓名」「收款方姓名」「交易流水号」就认作平安银行借记卡账单。

文件可以是 `.xls` 或 `.xlsx`，有些 `.xls` 实际是 XLSX 格式，也能读。第 1 行是账户信息，卡号后四位从其中打码的卡号（如 `6230****1234`）里取；第 2 行是表头；第 3 行起是交易。

金额的正负由「交易类型」决定：`转入` 是收入，`转出` 是支出。收款方在转入时取付款方姓名，转出时取收款方姓名。描述由「摘要」、收款方和「备注」拼成，备注与收款方相同时不重复，超过 50 个字时截断并加 `...`。「交易流水号」记为 `order_id`。

## 配置示例

```yaml title="bean-sieve.yaml" config
providers:
  pab_debit:
    accounts:
      "1234": Assets:Bank:PAB
    balance: true

rules:
  - description: "代发工资"
    contra_account: Income:Salary
  - description: "跨行转出"
    contra_account: Assets:Bank:CMB
```

`accounts` 的键是卡号后四位。网银每次导出一张卡的明细，有几张卡就列几项；对账时只把这份文件那张卡对应的账户纳入 Extra 检查。

`balance: true` 会在输出末尾追加一条 `balance` 断言，金额取这张卡最后一笔交易后的账户余额，日期是该笔交易的次日。

## 解析出的元数据字段

| 字段 | 来源列 | 说明 |
| :--- | :--- | :--- |
| `time` | 交易时间 | 时分秒 |
| `order_id` | 交易流水号 | |
| `tx_type` | 交易类型 | `转入` 或 `转出` |
| `summary` | 摘要 | |
| `note` | 备注 | 完整原文 |
| `counterparty_account` | 付款方账号或收款方账号 | 转入取付款方，转出取收款方 |
| `balance` | 账户余额 | |

默认全部输出，空值会被略去。要只输出其中几项，在 `defaults.output_metadata` 里列出字段名；`providers.pab_debit.output_metadata` 列出的字段会追加到全局列表上。

## 已知限制

- 金额是数字单元格，输出时不补齐两位小数：`7500.00` 写成 `7500`，`1.30` 写成 `1.3`。数值不变，匹配不受影响，但格式和账本里的其他条目不一致。`balance` 断言也是这样。
- 金额一律按人民币处理。
- 对账范围是这张卡第一笔到最后一笔交易的日期，账本里晚于最后一笔交易的条目不会报 Extra。

## 输出样例

仓库的 [`examples/pab_debit/`](https://github.com/Xm798/bean-sieve/tree/master/examples/pab_debit) 目录是一组虚构数据，也是端到端测试的输入。在该目录下运行：

```bash
bean-sieve reconcile 平安银行借记卡流水.xlsx -c bean-sieve.yaml -l ledger.bean -o pending.bean
```

账本里已有的 12 月 27 日晚餐被匹配，不再输出；金额写成 `7500`、`1.3` 这样，没有补齐两位小数；账本里 12 月 18 日那笔在账单里找不到，被列为 Extra；末尾的 `balance` 断言取最后一笔交易后的余额，日期是 12 月 28 日。
