## 账单下载方式

广发银行信用卡每月把电子账单发到预留的邮箱，名下各卡的交易在同一封邮件里按卡分段列出。还没开通邮件账单时，到广发银行的信用卡渠道设置账单邮箱，具体入口以银行说明为准。

收到账单后，在邮件客户端把整封邮件保存为 `.eml` 文件：

| 客户端 | 操作 |
| :--- | :--- |
| Gmail 网页版 | 打开邮件，点右上角「⋮ → 下载邮件」 |
| Apple Mail | 把邮件从列表拖到访达 |
| Thunderbird | 选中邮件，「文件 → 另存为 → 文件」 |

只复制正文或另存为 HTML 得到的文件无法解析。

某个月没收到邮件时，可以向银行申请补发这个月的 PDF 账单，直接传入即可。

## 支持的文件格式与识别方式

<ProviderFacts id="cgb_credit" />

文件名里没有「广发信用卡」或「广发银行」时（比如样例的 `cgb_credit-2030-03.eml`），Bean-Sieve 会解码邮件标题和正文，或读取 PDF 第一页的文字，在里面找「广发银行信用卡」「广发信用卡」或「发现精彩」。较早的账单邮件标题用的是简称「广发信用卡」。补发 PDF 的银行名称只出现在标志图片里，文字中没有，所以靠第一页提到的广发 App「发现精彩」识别。

邮件和 PDF 的内容相同。正文按卡分段，每段以「卡号：6200********1234」开头。每行交易有交易日期、入账日期、`(类型)摘要`、交易金额、交易货币、入账金额、入账货币。类型是「消费」「还款」「赠送」之一，保留在描述开头，如 `(消费)store-e`。日期是 `YYYY/MM/DD`，取交易日期。对账范围取账单周期，邮件里写作「账单周期:2030/03/01-2030/03/31」，PDF 里写作「账单周期 2030/03/01 - 2030/03/31」。

2024 年及更早的邮件版式略有不同：账单周期写作「本期账单周期：2030/02/14至2030/03/13」；交易行没有入账货币一列，入账货币取账单开头账户信息表里这张卡的「入账货币」。双币卡在表里列两行，每笔交易按交易货币取对应的那一种。

卡的利息（如消费利息）单独一行列在交易之后、没有日期时，按账单周期最后一天记账，描述取原文，如 `消费利息`。

金额和币种取入账金额与入账货币，中文币种名换成 ISO 代码（人民币 → `CNY`、美元 → `USD`、港币 → `HKD` 等）。交易货币与入账货币不同时（境外交易，或外币卡上以第三种币种消费），原币金额和币种记入 `original_amount` 和 `original_currency`，对方科目写成原币，并以 `@@` 标注入账金额：

```beancount
2030-03-09 ! "(消费)overseas-shop-c"
    Liabilities:CreditCard:CGB:4321  -145.00 CNY
    Expenses:FIXME  20.00 USD @@ 145.00 CNY
```

匹配账本时，信用卡 posting 记的是入账金额，或者是原币金额和原币币种，都算同一笔，按原币导入的旧条目也能匹配上。

## 邮件与 PDF 同时传入

同一账单周期的邮件和 PDF 内容相同，一起传入时每张卡只采用邮件，PDF 里这张卡的交易不用，避免重复入账。终端输出的 Statement selection 会列出采用和丢弃的文件；两份的交易笔数或金额合计对不上时，还会给出一条 Mismatch 提示。

- 是否重叠按印出的账单周期判断，每张卡分开判断。
- 同一周期有两份 PDF 时，命令行里靠前的那份生效。
- 加 `--keep-overlap` 跳过这一步，所有文件的交易都保留。

## 配置示例

广发银行信用卡按卡管理：各卡账单日合并为同一天，但每张卡独立还款，账本里通常每张卡建一个账户。`accounts` 的键是卡号后四位：

```yaml title="bean-sieve.yaml" config
providers:
  cgb_credit:
    accounts:
      "1234": Liabilities:CreditCard:CGB:1234
      "5678": Liabilities:CreditCard:CGB:5678

rules:
  - description: "赠送"
    contra_account: Income:Rebate:CGB
  - description: "网银还款"
    contra_account: Assets:Bank:Checking
```

规则的 `description` 匹配的是带类型前缀的描述，可以直接按 `(赠送)` 这类类型写规则；元数据 `trans_type` 里也有同样的类型。

## 解析出的元数据字段

| 字段 | 来源列 | 说明 |
| :--- | :--- | :--- |
| `card_last4` | 卡号 | 取所在分段的卡号后四位 |
| `original_date` | 交易日期 | 原文，`YYYY/MM/DD`；利息行没有 |
| `trans_type` | 摘要前的类型 | `消费`、`还款` 或 `赠送`；利息行没有 |
| `original_amount` | 交易金额 | 仅在交易货币与入账货币不同时出现 |
| `original_currency` | 交易货币 | 与 `original_amount` 一起出现 |

默认全部输出。要只输出其中几项，在 `defaults.output_metadata` 里列出字段名；`providers.cgb_credit.output_metadata` 列出的字段会追加到全局列表上。

## 已知限制

- 币种对照表收录了人民币、美元、港币、澳门元、新台币、欧元、英镑、日元、韩元、新加坡元、澳大利亚元（澳元）、加拿大元、瑞士法郎、新西兰元、泰铢。交易货币不在表里时给出警告，这笔交易照常入账，但不记 `original_amount`。入账货币不在表里时给出警告，改按账户信息表里这张卡的入账货币记账；表里也查不到，或双币卡的交易货币和两种入账货币都对不上时，略过这笔交易并给出警告。
- 读不出账单周期的文件给出警告，交易照常解析，但不参与邮件与 PDF 的去重，没有日期的利息行也会被略过。
- 交易行是从正文文字里按格式匹配出来的，金额和币种取行尾的那一组，摘要里的「5 美元 6」这类文字留在摘要里。银行调整账单格式后，读不出金额和币种的交易行给出警告后略过；日期不存在（如 2 月 30 日）的行同样给出警告后略过。
- 账单中出现 `accounts` 没有列出的卡号时，这些交易的账户输出为 `Assets:FIXME`。

## 输出样例

仓库的 [`examples/cgb_credit/`](https://github.com/Xm798/bean-sieve/tree/master/examples/cgb_credit) 目录是一组虚构数据，也是端到端测试的输入。在该目录下运行：

```bash
bean-sieve reconcile cgb_credit-2030-02.pdf cgb_credit-2030-03.eml -c bean-sieve.yaml -l ledger.bean -o pending.bean
```

2 月只有 PDF 账单。两份账单里都有两张卡，交易分别记到各自的账户。账本里已有的 3 月 3 日消费被匹配，不再输出；3 月 9 日的美元消费按人民币入账，对方科目写成 `20.00 USD @@ 145.00 CNY`；账本里 3 月 25 日那笔在账单里找不到，被列为 Extra。
