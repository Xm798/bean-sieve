## 账单下载方式

浦发银行信用卡的邮件账单里有跳转到网银账单页面的入口，在那个页面导出交易明细，得到一个 `.xls` 文件。名下所有卡的交易在同一份文件里。页面上的按钮名称以实际页面为准。

导不出交易明细的月份，可以向银行申请 PDF 账单，每月一份，同样包含名下所有卡。

## 支持的文件格式与识别方式

<ProviderFacts id="spdb_credit" />

Bean-Sieve 按表头识别 `.xls`：第一个工作表的前 10 行里有一行正好是交易日期、记账日期、交易摘要、卡号末四位、卡片类型、交易币种、交易金额、原始交易金额&币种这八列，就认作浦发银行信用卡。文件名叫什么都可以。

`.pdf` 只看内容：第一页里有「浦发个人信用卡对账单」就认作浦发银行信用卡。文件名里的「浦发」「spdb」不算数，因为浦发借记卡的 PDF 回单也可能这样命名。

PDF 账单读「本期账务明细」里的交易，表格跨页时接着往下读。每行有交易日期、记账日期、交易摘要、卡号末四位、交易金额；新版账单还多一列原始交易金额&币种，旧版没有。摘要折成多行时会拼回一行。交易金额前的 `￥` 记为 CNY，`$` 记为 USD。解析出的交易和 `.xls` 的一样，只是没有卡片类型。

日期是 `YYYYMMDD`，取交易日期。金额和币种取交易金额与交易币种，负数是还款或退款。卡号后四位被 Excel 存成数字、丢了开头的 0 时，会补回四位。

「原始交易金额&币种」形如 `5.00(美元)` 时，原币金额和币种记入 `original_amount` 和 `original_currency`，对方科目写成原币，并以 `@@` 标注入账金额：

```beancount
2030-05-10 ! "境外消费 merchant-x"
    Liabilities:CreditCard:SPDB  -36.00 CNY
    Expenses:FIXME  5.00 USD @@ 36.00 CNY
```

匹配账本时，信用卡 posting 记的是入账金额，或者是原币金额和原币币种，都算同一笔，按原币导入的旧条目也能匹配上。

导出文件里没有账单周期，每张卡的对账范围取这张卡第一笔到最后一笔交易的日期。PDF 账单标题写着账单月份（如 `203004信用卡账单`），账户信息里写着账单日，账单周期按上月账单日的次日到本月账单日计算，对账范围取这个周期，再放宽到包含周期外的交易日期。

### 同一账期传入交易明细和 PDF

同一个月的 `.xls` 和 PDF 一起传入时，每张卡只采用 `.xls`，PDF 里这张卡的交易全部丢弃，和两个文件在命令行上的先后无关。没有 `.xls` 的月份，PDF 没有对手，直接采用。

判断两个文件是否同一账期，PDF 用账单周期，`.xls` 用记账日期的范围。记账日期都落在账单周期内，交易日期可能早于周期，所以 `.xls` 不会和上个月的 PDF 重叠。两份文件的交易笔数或合计金额不一致时，命令行会提示。

PDF 里看不出是正本还是补发，所以所有 PDF 一律排在 `.xls` 之后。

## 配置示例

浦发银行信用卡按户管理：名下所有卡共用一个额度、一份账单，账本里通常也只建一个账户。`accounts` 的键是卡号后四位，把每张卡都指向这个账户：

```yaml title="bean-sieve.yaml" config
providers:
  spdb_credit:
    accounts:
      "1234": Liabilities:CreditCard:SPDB
      "5678": Liabilities:CreditCard:SPDB
    posting_metadata:
      - card_last4

rules:
  - description: "还款"
    contra_account: Assets:Bank:Checking
```

多张卡共用一个账户时，账户名看不出是哪张卡。`posting_metadata` 里写上 `card_last4`，输出时会把卡号后四位写在信用卡 posting 下面。

要进一步检查账本里已有的条目，可以把账户列入 `diagnostics.meta_check_accounts`。Bean-Sieve 会在匹配到的条目缺少 `card_last4` 或与账单不一致时输出提示，匹配结果不受影响：

```yaml title="bean-sieve.yaml" config-partial
diagnostics:
  meta_check_accounts:
    - Liabilities:CreditCard:SPDB
```

交易摘要写入描述，收款方为空，可以用规则的 `target_payee` 补上。

## 解析出的元数据字段

| 字段 | 来源列 | 说明 |
| :--- | :--- | :--- |
| `card_last4` | 卡号末四位 | |
| `card_type` | 卡片类型 | 为空或 `-` 时不出现；PDF 账单没有这一列 |
| `original_amount` | 原始交易金额&币种 | 形如 `金额(币种)` 时出现；旧版 PDF 账单没有这一列 |
| `original_currency` | 原始交易金额&币种 | 与 `original_amount` 一起出现 |
| `original_transaction` | 原始交易金额&币种 | 该列有内容、但不是 `金额(币种)` 格式时保留原文 |

默认全部输出。要只输出其中几项，在 `defaults.output_metadata` 里列出字段名；`providers.spdb_credit.output_metadata` 列出的字段会追加到全局列表上。

## 已知限制

- `.xls` 的对账范围只到每张卡第一笔和最后一笔交易的日期，账本里在这之前或之后的条目不会被报为 Extra。
- PDF 只印本月账单日，周期起点按上月同一天推算。银行改过账单日的那个月，推算的起点会和实际差几天。
- 旧版 PDF 账单没有原始交易金额列，境外交易只有入账金额，对方科目不会写成原币。
- 币种名只认人民币、美元、港币、澳门元、新台币、欧元、英镑、日元、韩元、新加坡元、澳大利亚元（澳元）、加拿大元、瑞士法郎、新西兰元、泰铢，其他币种名转成大写后原样写进输出。
- 日期、金额、币种或摘要无法解析的行会被跳过，并在日志里给出警告。PDF 里金额前不是 `￥` 或 `$` 的行也一样。
- 账单中出现 `accounts` 没有列出的卡号时，这些交易的账户输出为 `Assets:FIXME`。

## 输出样例

仓库的 [`examples/spdb_credit/`](https://github.com/Xm798/bean-sieve/tree/master/examples/spdb_credit) 目录是一组虚构数据，也是端到端测试的输入。在该目录下运行：

```bash
bean-sieve reconcile 浦发银行信用卡交易明细2030年05月.xls 浦发银行信用卡电子账单2030年04月.pdf 浦发银行信用卡电子账单2030年05月.pdf -c bean-sieve.yaml -l ledger.bean -o pending.bean
```

账单里有两张卡，配置把它们都指向 `Liabilities:CreditCard:SPDB`，信用卡 posting 下写了 `card_last4`。4 月只有 PDF，其中的消费、退货、分期和还款都输出了，分期摘要折行后拼成一行。5 月同时有 `.xls` 和 PDF，只采用 `.xls`，PDF 的 5 月交易没有重复输出。账本里已有的 5 月 3 日消费被匹配，不再输出；5 月 10 日的美元消费写成 `5.00 USD @@ 36.00 CNY`；账本里 5 月 13 日那笔在账单里找不到，被列为 Extra。
