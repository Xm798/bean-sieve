## 账单下载方式

登录[建设银行个人网上银行](https://ibsbjstar.ccb.com.cn/CCBIS/V6/STY1/CN/login.jsp)，查询账户明细后导出 XLS 文件。用 Chrome 即可，不需要安全控件。

导出的文件名形如 `交易明细_1234_20300601_20300630.xls`，中间四位是卡号后四位。改过名的文件也能识别，见下一节。

## 支持的文件格式与识别方式

<ProviderFacts id="ccb_debit" />

文件名不符合上面的格式时，Bean-Sieve 会读 XLS 的前 10 行，标题是 `China Construction Bank` 或「中国建设银行个人活期账户」，且有「交易日期」表头，就认作建设银行借记卡账单。

文件是 XLS，前几行是开户行、币种、账号等信息，接着是表头，最后一行「以上数据仅供参考」之后的内容不再读取。卡号后四位从账号行里取：打码的卡号取末四位，完整的「卡号/账号」也取末四位；都取不到时从文件名里取。

导出有两种列布局，Bean-Sieve 按表头文字找列：

- 收支分列：有「交易时间」，金额分「支出」「收入」两列，对方信息分「对方账号」「对方户名」两列，地点取「交易地点」。
- 单列金额：只有「交易日期」，没有时间；「交易金额」带正负号，负数是支出；对方信息在「对方账号与户名」一列，写成 `账号/户名`，没有账号时只有户名；地点取「交易地点/附言」。

表头里缺日期列或金额列时，解析直接报错。

描述由「摘要」和地点拼成，收款方取对方户名，值为 `0` 时视为空。

## 配置示例

```yaml title="bean-sieve.yaml" config
providers:
  ccb_debit:
    accounts:
      "1234": Assets:Bank:CCB

rules:
  - description: "代发工资"
    contra_account: Income:Salary
  - description: "信用卡还款"
    contra_account: Liabilities:CreditCard:CCB
```

`accounts` 的键是卡号后四位。网银每次导出一张卡的明细，有几张卡就列几项；对账时只把这份文件那张卡对应的账户纳入 Extra 检查。

加 `balance: true` 会在输出末尾追加一条 `balance` 断言，金额取这张卡最后一笔交易后的账户余额，日期是该笔交易的次日。

## 解析出的元数据字段

| 字段 | 来源列 | 说明 |
| :--- | :--- | :--- |
| `time` | 交易时间 | 时分秒，单列金额布局没有 |
| `summary` | 摘要 | |
| `balance` | 账户余额 | 值为 `0` 时不出现 |
| `counterparty_account` | 对方账号，或「对方账号与户名」里的账号 | 值为 `0` 时不出现 |
| `location` | 交易地点，或交易地点/附言 | |

默认全部输出，空值会被略去。要只输出其中几项，在 `defaults.output_metadata` 里列出字段名；`providers.ccb_debit.output_metadata` 列出的字段会追加到全局列表上。

## 已知限制

- XLS 里的金额是数字单元格，输出时不补齐两位小数：`7000.00` 写成 `7000`，`1.80` 写成 `1.8`。数值不变，匹配不受影响，但格式和账本里的其他条目不一致。`balance` 元数据和 `balance` 断言也是这样。
- 金额一律按人民币处理。
- 对账范围是这张卡第一笔到最后一笔交易的日期，账本里晚于最后一笔交易的条目不会报 Extra。

## 输出样例

仓库的 [`examples/ccb_debit/`](https://github.com/Xm798/bean-sieve/tree/master/examples/ccb_debit) 目录是一组虚构数据，也是端到端测试的输入。在该目录下运行：

```bash
bean-sieve reconcile 交易明细_1234_20300601_20300630.xls -c bean-sieve.yaml -l ledger.bean -o pending.bean
```

账本里已有的 6 月 26 日晚餐被匹配，不再输出；输出的金额没有补齐两位小数，如 `7000`、`1.8`；账本里 6 月 18 日那笔在账单里找不到，被列为 Extra。
