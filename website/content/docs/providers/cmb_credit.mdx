## 账单下载方式

招商银行信用卡每月把电子账单发到绑定的邮箱，邮件标题为「招商银行信用卡电子账单」。还没开通时，在掌上生活 App 或招商银行 App 把账单寄送方式改为电子邮件。

收到账单后，在邮件客户端把整封邮件保存为 `.eml` 文件：

| 客户端 | 操作 |
| :--- | :--- |
| Gmail 网页版 | 打开邮件，点右上角「⋮ → 下载邮件」 |
| Apple Mail | 把邮件从列表拖到访达 |
| Thunderbird | 选中邮件，「文件 → 另存为 → 文件」 |

只复制正文或另存为 HTML 得到的文件无法解析。

早年的部分账单邮件只有汇总，没有逐笔交易。这些月份可以向招商银行申请补发账单，拿到的是可以直接选中文字的 PDF，页脚写着「招商银行信用卡对账单（……）（补）」，Bean-Sieve 也能解析。

## 支持的文件格式与识别方式

<ProviderFacts id="cmb_credit" />

文件名不含「招商银行信用卡」或「招行信用卡」也没关系：邮件会解码标题和正文，PDF 读取第一页文字，在里面找「招商银行信用卡」。

邮件有两种版式。现在的邮件在交易表格上方用文字写出各列名称，Bean-Sieve 按列名取值；较早的邮件表头是一张图片，交易地写在交易地金额前面，按这个固定顺序读取。有逐笔交易的邮件如果两种版式都对不上，终端会给出 `Unrecognised CMB statement layout` 警告，这份邮件按只有汇总处理。

账单按账户分段，人民币账户之外可能还有一段美元账户，这一段的交易币种记为 USD、金额列名为美元金额。两种格式的每行交易都包含交易日、记账日、交易摘要、人民币金额、卡号后四位、交易地金额和交易地，PDF 把交易地写在交易地金额后的括号里，如 `92.60(HK)`。日期取交易日，还款这类没有交易日的行取记账日。

邮件的账单月份依次取正文里的「YYYY年MM月信用卡账单」、旧版邮件印的账单周期（取结束日所在的月份）、邮件标题里的年月、文件名里的年月。都找不到时取当前月份，并给出 `No statement month` 警告。

账单只写月日。记账日取不晚于账单日的最近日期：PDF 印有账单日；旧版邮件取账单周期的结束日；新版邮件不印账单日，取账单月份的最后一天。交易日取不晚于记账日的最近日期。分期行的交易日是最初消费的日子，可能比账单早好几个月，会归到上一年。

## 邮件与补发 PDF 同时传入

同一个月的邮件和补发 PDF 内容相同，一起传入时，邮件里有的账户只采用邮件，PDF 里这些账户的交易不用，避免重复入账。邮件没有美元账户段而 PDF 有时，PDF 的美元交易照常采用。终端输出的 Statement selection 会列出采用和丢弃的文件；两份的交易笔数或金额合计对不上时，还会给出一条 Mismatch 提示。

- 判断是否同一个月按账单月份，范围取整个自然月；人民币账户和美元账户分开判断。
- 只有汇总、没有交易表格的邮件不参与选择，同月的 PDF 照常采用。
- 同一个月有两份 PDF 时，命令行里靠前的那份生效。
- 加 `--keep-overlap` 跳过这一步，所有文件的交易都保留。

## 配置示例

招商银行信用卡按户管理：名下所有卡共用一个额度、一份账单，账本里通常也只建一个账户。`accounts` 的键是卡号后四位，把每张卡都指向这个账户：

```yaml title="bean-sieve.yaml" config
providers:
  cmb_credit:
    accounts:
      "1234": Liabilities:CreditCard:CMB
      "5678": Liabilities:CreditCard:CMB
    posting_metadata:
      - card_last4

rules:
  - description: "还款"
    contra_account: Assets:Bank:Checking
```

多张卡共用一个账户时，账户名看不出是哪张卡。`posting_metadata` 里写上 `card_last4`，输出时会把卡号后四位写在信用卡 posting 下面。

要进一步检查账本里已有的条目，可以把账户列入 `diagnostics.meta_check_accounts`。Bean-Sieve 会在匹配到的条目缺少 `card_last4` 或与账单不一致时输出提示，匹配结果不受影响：

```yaml title="bean-sieve.yaml" config-partial
diagnostics:
  meta_check_accounts:
    - Liabilities:CreditCard:CMB
```

账单中的交易摘要写入描述，收款方为空，可以用规则的 `target_payee` 补上。

## 解析出的元数据字段

| 字段 | 来源列 | 说明 |
| :--- | :--- | :--- |
| `card_last4` | 卡号末四位 | |
| `posting_date` | 记账日 | 仅在记账日与交易日不同时出现 |
| `original_amount` | 交易地金额 | 仅在与入账金额不同时出现（境外交易），只有数字，不带币种 |
| `country` | 交易地 | 国家或地区代码，如 `HK`，与 `original_amount` 一起出现；部分 PDF 不印交易地，这时没有这一项 |

默认全部输出。要只输出其中几项，在 `defaults.output_metadata` 里列出字段名；`providers.cmb_credit.output_metadata` 列出的字段会追加到全局列表上。

## 已知限制

- 账单不写交易地金额的币种，所以境外交易只按入账金额（人民币或美元）记账，原币金额记在 `original_amount` 里，不生成 `@@` 价格。
- 对账范围取账单月份的整个自然月（如 2030 年 3 月账单取 3 月 1 日至 31 日），再按每张卡的交易日期向外扩展。账单日不在月末时，这个范围和实际账单周期并不一致，Extra 结果需要人工核对。
- 账单中出现 `accounts` 没有列出的卡号时，这些交易的账户输出为 `Assets:FIXME`。PDF 里少数行不印卡号，在按卡号配置的 `accounts` 下也会输出为 `Assets:FIXME`。
- 分期行的交易日是最初消费的日子，对账范围会按它向前扩展（其他银行也是这样），所以只对一个月时，账本里几个月前的条目也可能被列为 Extra。后续会改为按记账日确定范围。

## 输出样例

仓库的 [`examples/cmb_credit/`](https://github.com/Xm798/bean-sieve/tree/master/examples/cmb_credit) 目录是一组虚构数据，也是端到端测试的输入。在该目录下运行：

```bash
bean-sieve reconcile 招商银行信用卡电子账单2030年01月.eml 招商银行信用卡电子账单2030年03月.eml reissue-2030-03.pdf reissue-2030-02.pdf -c bean-sieve.yaml -l ledger.bean -o pending.bean
```

目录里有 1 月的旧版邮件账单、3 月的新版邮件账单（含美元账户段），以及 3 月和 2 月的补发 PDF。1 月的邮件表头是图片，账单月份取自账单周期。3 月的 PDF 和邮件重复，被整份丢弃；2 月没有邮件，交易来自 PDF，其中分期行的交易日是上一年 9 月。账单里有两张卡，配置把它们都指向 `Liabilities:CreditCard:CMB`。账本里已有的 3 月 3 日消费被匹配，不再输出；美元账户段的两笔记为 USD；境外消费带上了 `original_amount` 和 `country`；账本里 3 月 25 日那笔在账单里找不到，被列为 Extra。
