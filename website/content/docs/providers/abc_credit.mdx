## 账单下载方式

农业银行信用卡按卡出账单，每张卡每月一封电子账单邮件。还没开通邮件账单时，到农业银行的信用卡渠道设置账单邮箱，具体入口以银行说明为准。

收到账单后，在邮件客户端把整封邮件保存为 `.eml` 文件，每张卡的账单各存一份：

| 客户端 | 操作 |
| :--- | :--- |
| Gmail 网页版 | 打开邮件，点右上角「⋮ → 下载邮件」 |
| Apple Mail | 把邮件从列表拖到访达 |
| Thunderbird | 选中邮件，「文件 → 另存为 → 文件」 |

只复制正文或另存为 HTML 得到的文件无法解析。

某个月没收到邮件时，可以向银行申请补发这个月的 PDF 账单（标题为「农业银行信用卡对账单2030年03月（补）」这样的格式），直接传入即可。

## 支持的文件格式与识别方式

文件名里没有「农业银行」或「金穗信用卡」时，Bean-Sieve 会解码邮件标题和正文，或读取 PDF 第一页的文字，在里面找「金穗信用卡电子对账单」或「农业银行信用卡对账单」。

邮件和 PDF 的明细相同。明细表每行有交易日期、入账日期、卡号后四位、交易描述、交易金额/币种、入账金额/币种六列。日期是 `YYMMDD` 格式，金额和币种取入账金额一列。

附属卡的行在卡号后面带「附」字（如 `5678附`），取前四位。约定还款这类账户级的行卡号为空，归到账单抬头那张卡上。对账范围取账单上的账单周期，如 `2030/03/01-2030/03/31`。

## 邮件与 PDF 同时传入

同一账单周期的邮件和 PDF 内容相同，一起传入时每张卡只采用邮件，PDF 里这张卡的交易不用，避免重复入账。被丢弃的 PDF 也不出现在核对报告里。终端输出的 Statement selection 会列出采用和丢弃的文件；两份的交易笔数或金额合计对不上时，还会给出一条 Mismatch 提示。

- 是否重叠按印出的账单周期判断，每张卡分开判断，附属卡单独算一张。
- 同一周期有两份 PDF 时，命令行里靠前的那份生效。
- 加 `--keep-overlap` 跳过这一步，所有文件的交易都保留。

## 配置示例

农业银行信用卡按卡管理，每张卡独立出账单、独立还款，账本里通常每张卡建一个账户。`accounts` 的键是卡号后四位：

```yaml title="bean-sieve.yaml" config
providers:
  abc_credit:
    accounts:
      "1234": Liabilities:CreditCard:ABC:1234
      "5678": Liabilities:CreditCard:ABC:5678
    rebate_income_account: Income:Rebate:ABC
    rebate_keywords:
      - 刷卡金

rules:
  - description: "约定还款"
    contra_account: Assets:Bank:Checking
```

附属卡的交易出现在主卡的账单里。要把附属卡的消费记到主卡账户，就把附属卡的后四位也指向主卡账户。

### 刷卡金与账单核对

农业银行账单会列出本期使用的刷卡金，交易明细里却没有对应的行。对账结束后，Bean-Sieve 在输出末尾给每张卡附一份核对报告：

- 解析消费：明细里所有支出的合计
- 账单消费：账务说明里的「本期账单金额」
- 账单应还：「本期应还款额」
- 刷卡金抵扣：「本期使用刷卡金」和「本期调整金额」中较小的一个

补发 PDF 不印账务说明和刷卡金，它的报告没有账单消费和刷卡金抵扣两项，解析消费直接和账单应还比较。上期有欠款或本期有还款、退款时，这个比较会显示差额，需要人工核对。

解析消费等于账单消费时，报告显示平账。本期用过刷卡金的，还会生成一条刷卡金分录：日期取账单周期最后一天，贷方记入 `rebate_income_account`（不配置时为 `Income:Rebate:ABC`），信用卡账户取 `accounts` 里这张卡的账户（未配置时为 `Liabilities:Credit:ABC:<后四位>`）。两者不相等时，报告只列出差额，不生成刷卡金分录。

用刷卡金付的消费退款后，银行会收回这部分刷卡金，「本期调整金额」里只剩净额，所以抵扣额取两者中较小的那个。调整金额超过刷卡金使用额时，报告会提示差额需要手工核对。

账本里已经记过这笔刷卡金时，Bean-Sieve 不会重复生成。它在 Extra 条目里找同时满足以下条件的一条：

- 日期在账单周期内
- 信用卡 posting 的账户名包含卡号后四位
- 金额等于刷卡金抵扣额
- 收款方或描述含 `rebate_keywords` 中的某个词，或者有一条 posting 记在 `rebate_income_account` 上

找到了，报告显示「刷卡金 X.XX 已记录」。`rebate_income_account` 和 `rebate_keywords` 都不配置时不查找，每次都会生成分录。

输出末尾的分录和报告如下（取自下方的样例）：

```beancount
; --- 刷卡金抵扣 ---
2030-03-31 * "农业银行" "刷卡金抵扣 (尾号4321)"
  Liabilities:CreditCard:ABC:4321  5.00 CNY
  Income:Rebate:ABC
; ============================================================
; 农业银行信用卡 账单核对
; ============================================================
;
; 卡号: 620000******4321 (尾号 4321)
; 账单周期: 2030/03/01-2030/03/31
;
;   解析消费:             220.00 CNY
;   账单消费:             220.00 CNY
;   账单应还:              95.00 CNY
;   刷卡金抵扣:             5.00 CNY
;
;   状态: ✅ 平账 (刷卡金 5.00)
; ============================================================
```

文件改过名或用 `-p abc_credit` 显式指定 Provider 的账单，同样会出现在核对报告里。

## 解析出的元数据字段

| 字段 | 来源列 | 说明 |
| :--- | :--- | :--- |
| `card_last4` | 卡号后四位 | 附属卡去掉「附」字；卡号为空的行取账单抬头的卡号 |

默认输出。在 `defaults.output_metadata` 里列出字段名后，只输出列出的字段。

## 已知限制

- 只读取入账金额和入账币种，交易金额一列不解析。境外交易没有 `original_amount`，也不生成 `@@` 价格。
- 刷卡金去重只看账户名里有没有卡号后四位。账本里的信用卡账户名不带卡号时，已记过的刷卡金找不到，每次都会重新生成分录。
- 核对报告只比较支出合计，还款和退款不参与比较。
- 列数不是六列、但看起来像交易的明细行会被跳过，并在日志里给出警告。
- 账单中出现 `accounts` 没有列出的卡号时，这些交易的账户输出为 `Assets:FIXME`。

## 输出样例

仓库的 [`examples/abc_credit/`](https://github.com/Xm798/bean-sieve/tree/master/examples/abc_credit) 目录是一组虚构数据，也是端到端测试的输入。在该目录下运行：

```bash
bean-sieve reconcile 农业银行信用卡对账单2030年02月（补）.pdf 农业银行金穗信用卡2030年03月电子账单.eml -c bean-sieve.yaml -l ledger.bean -o pending.bean
```

2 月只有 PDF 账单，报告里这张卡的解析消费和账单应还都是 144.00。账本里已有的 3 月 3 日消费被匹配，不再输出；账本里 3 月 25 日那笔在账单里找不到，被列为 Extra。明细的支出合计 220.00 与账单消费一致，报告显示平账，并补了一条 5.00 的刷卡金分录。
